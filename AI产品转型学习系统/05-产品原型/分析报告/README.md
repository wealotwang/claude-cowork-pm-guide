# 分析报告

合规工作台的第 4 个模块。它**不重新跑评测**，只读 `../命中结果/hits_*.json`，把"一堆逐条结果"变成"能指导下一步动作的分析"。

它替代的是原来手工维护的 [`../../03-学习成果/Day06-CSV50-跑分报告.html`](../../03-学习成果/Day06-CSV50-跑分报告.html)——那份报告里的数字要手工同步，跑分一变就容易对不上；这个是从命中结果自动算出来的。

## 为什么需要这个模块

Day07 的真实体验：跑出"高危 Recall 87%"之后卡住了，因为看着这个数字不知道该干什么。剩下的 13% 里，有多少是规则写得不好、有多少是那条 case 属于压根没实现的类别？分不清就没法决定下一步优化哪儿。

所以这个模块的核心不是"把数字画得好看"，是**把失败按"我该拿它怎么办"分开**。

## 三件事

### 1. 失败根因分三桶

| 桶 | 含义 | 该怎么办 |
|---|---|---|
| `real_miss` 范围内真实误判 | 该判对却判错了 | 规则该改的部分，逐条看 rationale 判断是规则说明不清楚还是缺边界示例 |
| `runtime_error` 调用/解析层报错 | LLM 返回空/截断/解析失败 | 内部实现层的稳定性问题，跟规则内容无关 |
| `out_of_scope` 未实现类别的自然miss | 期望类别压根没做（02/04/08/09） | 不是bug，要么接受收敛、要么去实现新类别 |

`real_miss` 还会再按方向细分，因为漏报和误报的严重性完全不一样：

- **漏报高危**：真违规被放过——最严重，这是 release blocker
- **误伤合规**：合规内容被拦——影响可用性，销售会烦
- **同风险等级内串类**：风险判断对了，具体归到哪一类不准——相对没那么急
- **风险等级判断偏移**：其他等级错配

### 2. 范围内准确率

单独算一个排除掉未实现类别之后的准确率。这两个数经常差很多——同一次跑分整体 60%、范围内 91%，差的那 31 个百分点全是"本来就没做"而不是"做坏了"。汇报时用整体数会低估当前规则质量，只用范围内数又会高估产品完成度，两个都得看。

### 3. 自动跟上次比

自动找同一数据集的上一次跑分，对比准确率、高危 Recall、报错数。避免"改完感觉好像好了一点"这种没有依据的判断。

第一次跑某个数据集时没有可比对象，会明确说明而不是留空。

## 用法

网页上走「④ 分析报告」tab 最方便。命令行：

```bash
cd "05-产品原型/分析报告"
python3 report.py                # 不带参数：列出所有历史跑分
python3 report.py 20260807_195837   # 生成分析 + 导出HTML
```

## 导出的 HTML

点"导出HTML"或跑命令行会生成 `报告_<跑分ID>.html`，是个不依赖服务的独立文件，可以直接发给别人、也适合面试时展示。

导出文件默认不提交 git（`.gitignore` 忽略了 `报告_*.html`），因为它是派生产物、随时能从命中结果重新生成。要保留某一份作为里程碑证据，`git add -f` 强制加进去即可。

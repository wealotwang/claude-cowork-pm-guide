# 05-产品原型

这是 `AI Compliance Check Assistant` 这个产品本身的家——不是"第几天学了什么"，是"这个产品现在长什么样"。

跟 `03-学习成果/` 的关系：`03-学习成果/DayXX-学习卡.md` 记录的是每天的学习过程和心得（历史，不改），这里存放的是产品当前真正生效的文件（会持续演进）。改动历史看 [CHANGELOG.md](./CHANGELOG.md)，不用去每个Day的学习卡里拼凑"规则到底改过几次"。

---

## 快速开始

```bash
cd "05-产品原型"
python3 server.py
# 浏览器打开 http://127.0.0.1:8787　（不是双击 index.html 文件本身，是访问这个网址）
```

纯 Python 标准库，不用 `pip install` 任何东西。四个tab里，只有②规则执行点"运行评测"时才需要 LLM key，另外三个tab不用。

**key 只需要配一次，以后每次开新终端都会自动生效**，不用每次手动 `export`：在 `05-产品原型/.env` 里写一行

```
DEEPSEEK_API_KEY=你的key
```

`checker.py` 启动时会自动读这个文件（找不到环境变量里的 key 时才会用它，手动 `export` 出来的值优先级更高，不会被覆盖）。这个文件不会被打印、不会被提交 git（`.gitignore` 已覆盖 `.env`），只在你本机生效。

## 产品结构：合规工作台四个模块

四个模块共用一个后端（`server.py`）和一个前端页面（`index.html`）的四个 tab，串成一条完整的闭环：**配规则 → 跑评测 → 看命中结果 → 出分析报告 → 回去改规则**。

| 模块 | 状态 | 位置 | 做什么 |
|---|---|---|---|
| ① 规则配置 | ✅ | [`规则配置/`](./规则配置/) | 唯一生效的规则配置（`rules_config.json`），网页可视化编辑，不用手改JSON |
| ② 规则执行 | ✅ | [`规则执行/`](./规则执行/) | 选数据集一键跑评测，结果自动落盘 |
| ③ 命中结果 | ✅ | [`命中结果/`](./命中结果/) | 历史跑分列表 + 逐条结果查看，可按通过/不符/报错筛选 |
| ④ 分析报告 | ✅ | [`分析报告/`](./分析报告/) | 从命中结果自动生成分析，可导出独立HTML |
| 数据集 | ✅ | [`数据集/`](./数据集/) | 所有评测数据的统一入口，丢CSV进去自动出现在下拉框里 |

用户端（医药代表录入CRM拜访表单的界面）目前还是静态mockup：[`../03-学习成果/Day05-AI-Compliance-双端Mockup.html`](../03-学习成果/Day05-AI-Compliance-双端Mockup.html)，还没有迁移进来，属于后续工作。

## 每个 tab 具体怎么用

### ① 规则配置

改规则说明、违规示例、边界示例，点"保存全部改动"直接写回 `规则配置/rules_config.json`。**不需要 API key**（这一步只读写文件，不调 LLM）。

保存时有基本校验：结构残缺或类目缺字段会被拒绝并提示原因，宁可不保存也不会把配置文件写坏。

这里改的全是自然语言，没有任何正则/代码——这是 Day07 那次架构调整定下的产品定位（详见 [`../03-学习成果/Day07-架构调整-去掉regex改纯LLM.md`](../03-学习成果/Day07-架构调整-去掉regex改纯LLM.md)）。

### ② 规则执行

选数据集 → 设并发数 → 点"运行评测"。需要提前在终端里配好 key 再启动 server.py，网页上不用输入 key。

跑完直接显示 release-gate 指标和失败详情，完整结果（含逐条 rationale）存到 `命中结果/hits_<时间戳>.json`。数据集有质量问题（比如分类ID不在 01-10 体系内）会在结果上方黄色提示。

并发数建议：小数据集用 1，200 条以上可以开到 4，看你的 API 速率限制。

### ③ 命中结果

历史跑分列表，最新在上，显示时间/数据集/条数/报错数/准确率。点任意一行看那次跑分的逐条结果，可以按「全部 / 类别不符 / 报错 / 通过」筛选。

跑分记录是**正式产物**而不是终端里一闪而过的输出——这样才能回答"上周那次跑分到底是什么结果""改规则之前是什么样"这类问题。

### ④ 分析报告

选一次跑分，生成分析。这个 tab 存在的理由是：光看"高危 Recall 87%"没法行动，得知道剩下那 13% 里哪些是该修的。所以报告做三件事：

**1. 失败按根因分三桶**——每桶对应完全不同的后续动作：

| 桶 | 含义 | 该怎么办 |
|---|---|---|
| 范围内真实误判 | 该判对却判错了 | 这才是规则该改的部分，逐条看 rationale |
| 调用/解析层报错 | LLM 返回空/截断 | 内部实现层的稳定性问题，跟规则内容无关 |
| 未实现类别的自然miss | 期望类别压根没做（02/04/08/09） | 不是bug，要么接受收敛、要么去实现新类别 |

真实误判还会再细分方向：漏报高危（最严重）、误伤合规、同风险等级内串类、风险等级偏移。

**2. 单独给一个"范围内准确率"**——排除掉没实现的类别之后，当前这套规则的真实水平。这两个数经常差很多：同一次跑分整体准确率 60%、范围内准确率可能有 91%，差的那部分全是"本来就没做"，不是"做坏了"。

**3. 自动跟上次比**——自动找同一数据集的上一次跑分，对比准确率、高危 Recall、报错数的变化，避免"改完感觉好像好了一点"这种错觉。

点"导出HTML"生成独立文件存到 `分析报告/报告_<跑分ID>.html`，可以直接发给别人看。这个是用来替代原来手工维护的 `Day06-CSV50-跑分报告.html` 的——数字自动来自命中结果，不用再手工同步。

## 也可以不开网页，用命令行

```bash
cd "05-产品原型/规则执行"
export DEEPSEEK_API_KEY="你的key"
python3 checker.py "要检查的一段文本"        # 单条测试
python3 run_eval.py                          # MVP子集评测
python3 run_eval_csv.py                      # 默认跑 ../数据集/csv50
python3 run_eval_csv.py ../数据集/200case-医药CRM合规压力测试集.csv --workers 4 --progress-every 20

cd "../分析报告"
python3 report.py                            # 不带参数：列出所有历史跑分
python3 report.py <run_id>                   # 生成分析 + 导出HTML
```

网页和命令行读的是同一份规则配置、同一套数据集解析逻辑（`规则执行/datasets.py`），不会出现"网页能跑、命令行跑不了"的情况。

## 为什么这样组织（而不是把day编号的文件直接改名完事）

1. **产品和学习记录要分开**：产品文件会被反复修改覆盖，学习记录应该保持"那天真实发生了什么"的历史快照。两者混在一起会导致"这份文件是历史快照还是当前生效版本"分不清——这正是这次重组要解决的问题
2. **旧文件不删除，只标注归档**：`03-学习成果/` 下所有 day 编号的规则/prompt/实现说明/demo脚本都还在，只是加了"已归档，当前生效版本见xxx"的提示。历史一点没丢，git log 和这些归档文件本身都能查到"哪天长什么样"
3. **一次只做一个模块**：按"规则配置→规则执行→命中结果→分析报告"顺序做，每完成一个都能独立验证、独立使用，不用等全部做完才能用

## 已知限制

- **大样本真实跑分还没做**：四个模块的链路都用 mock 掉的 LLM 调用完整验证过（包括 200 条数据集、4 并发、多次跑分对比、HTML 导出），但**用真实 API key 在大样本上的实际表现还没验证过**——耗时多久、稳定性如何、真实指标是多少，都需要你自己跑一次才知道
- **只实现了 10 类里的 6 类**：`02 / 04 / 08 / 09` 还没做，这是主动收敛的范围，不是遗漏。分析报告会把这部分单独归到"未实现类别的自然miss"桶里，不会混进"规则没写好"里
- **`06` 类容易被吸到 `01`**：Day07 已针对性补充了 01/06 边界说明，但还没在大样本上验证效果
- **输出稳定性**：300 case 那轮曾有约 9% 的 case 因 LLM 返回空/截断而报错。已加重试逻辑 + 把 `max_tokens` 从 300 调到 600，但这个组合拳在大样本上能收敛多少还没测过
- **没有接 RAG**：目前是纯文本分类，规则依据引用能力留到 demo 稳定之后再加

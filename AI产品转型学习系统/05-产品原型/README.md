# 05-产品原型

这是 `AI Compliance Check Assistant` 这个产品本身的家——不是"第几天学了什么"，是"这个产品现在长什么样"。

跟 `03-学习成果/` 的关系：`03-学习成果/DayXX-学习卡.md` 记录的是每天的学习过程和心得（历史，不改），这里存放的是产品当前真正生效的文件（会持续演进）。改动历史看 [CHANGELOG.md](./CHANGELOG.md)，不用去每个Day的学习卡里拼凑"规则到底改过几次"。

---

## 产品结构：合规工作台四个模块 + 用户端

合规审核这一侧规划为四个模块，一次做一个，不是一口气全做完：

| 模块 | 状态 | 位置 | 做什么 |
|---|---|---|---|
| 1. 规则配置 | ✅ 已完成 | [`规则配置/`](./规则配置/)（网页tab已并入根目录，见下） | 唯一生效的规则配置（`rules_config.json`），网页可视化编辑，不用手改JSON |
| 2. 规则执行 | ✅ 已完成 | [`规则执行/`](./规则执行/)（`checker.py`/`eval_cases.json`/`run_eval.py`/`run_eval_csv.py`） + 根目录 `server.py`/`index.html` 的"规则执行"tab | 网页上选数据集（MVP子集/完整CSV50/自定义CSV路径）一键跑评测，结果落盘到 `命中结果/` |
| 3. 命中结果 | 🔶 有产物，无独立UI | [`命中结果/`](./命中结果/)（文件夹本身已建好，跑评测时自动生成结果文件） | 目前每次跑评测都会存一份带时间戳的JSON（含summary+逐条结果），但还没有专门的"查看历史跑分"页面，得手动打开JSON看 |
| 4. 分析报告 | ⏳ 未开始 | 暂时还是手写维护的 `../03-学习成果/Day06-CSV50-跑分报告.html` | 目标是从命中结果自动生成，不再手工同步数字 |

用户端（医药代表录入CRM拜访表单的界面）目前还是静态mockup：[`../03-学习成果/Day05-AI-Compliance-双端Mockup.html`](../03-学习成果/Day05-AI-Compliance-双端Mockup.html)，还没有迁移进来，属于后续模块。

## 怎么用：一个后端 + 两个tab

规则配置和规则执行现在共用同一个本地服务（不用分别起两个server）：

```bash
export DEEPSEEK_API_KEY="你的key"   # 规则执行tab要跑评测才需要；只改规则不需要这一步
cd "05-产品原型"
python3 server.py
# 浏览器打开 http://127.0.0.1:8787
```

- **①规则配置tab**：改规则说明/违规示例/边界示例，点"保存全部改动"直接写回 `规则配置/rules_config.json`。不需要API key。
- **②规则执行tab**：选数据集（MVP子集约30条 / 完整CSV50 / 自定义CSV绝对路径，比如300 case）、可选设置并发数，点"运行评测"。需要提前在终端里配好 `DEEPSEEK_API_KEY`（或 `ANTHROPIC_API_KEY`）再启动server.py，网页本身不需要你输入key。跑完会显示release-gate指标（高危Recall/中危Precision/低危误报率）和失败详情，完整结果（含逐条rationale）落盘到 `命中结果/hits_<时间戳>.json`。

也可以不开网页，直接用CLI跑（`规则执行/`下用法和之前完全一致）：

```bash
cd "05-产品原型/规则执行"
export DEEPSEEK_API_KEY="你的key"
python3 checker.py "要检查的一段文本"
python3 run_eval.py
python3 run_eval_csv.py
```

## 为什么这样组织（而不是把day编号的文件直接改名完事）

1. **产品和学习记录要分开**：产品文件会被反复修改覆盖，学习记录应该保持"那天真实发生了什么"的历史快照，两者混在一起会导致"这份文件是历史快照还是当前生效版本"分不清——这正是这次重组要解决的问题
2. **旧文件不删除，只标注归档**：`03-学习成果/`下所有day编号的规则/prompt/实现说明文件都还在，只是加了"已归档，当前生效版本见xxx"的提示。历史一点没丢，git log和这些归档文件本身都能查到"哪天长什么样"
3. **一次只做一个模块**：完整的合规工作台是个不小的工程量，按"规则配置→规则执行→命中结果→分析报告"顺序做，每完成一个都能独立验证、独立使用，不需要等全部做完才能用

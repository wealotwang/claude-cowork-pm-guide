# 命中结果

这个文件夹存放"规则执行"模块每次跑评测产出的结果文件，由 `../server.py` 的 `/api/run`
接口自动写入，文件名格式：`hits_<年月日>_<时分秒>.json`（比如 `hits_20260807_195837.json`）。

## 文件结构

每个结果文件是一次完整的评测记录：

```json
{
  "run_id": "20260807_195837",
  "dataset": "mvp | csv50 | custom",
  "dataset_label": "人类可读的数据集说明",
  "custom_path": "如果是custom数据集，这里是CSV文件路径",
  "started_at": "开始时间",
  "finished_at": "结束时间",
  "summary": { "...": "release gate指标 + diagnostic指标，跟run_eval_csv.py的输出结构一致" },
  "results": [ "逐条case的输入/期望/实际/是否命中" ]
}
```

## 现状（Module 3 还没正式做）

目前这个文件夹只是"有产物"，还没有专门的网页页面来浏览/对比历史跑分记录——想看结果得
直接打开某个 `hits_*.json` 文件。把这些结果做成正式的"命中结果"模块（列表、筛选、
和分析报告模块打通）是 05-产品原型 的第 3 个模块，按"一个模块一个模块来"的节奏，
排在规则执行（已完成）后面。

## 关于git

这里的结果文件是每次本地跑评测的产物，不是需要长期维护的"当前生效配置"，跟
`规则配置/rules_config.json` 性质不一样。是否要把具体的 `hits_*.json` 提交到git、
提交哪些，看当时需要保留哪次跑分作为里程碑证据（比如面试前留一份CSV50或300 case的
完整结果方便展示），不需要每次跑完都提交。

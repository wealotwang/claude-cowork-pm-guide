# 命中结果

"规则执行"每跑一次评测，就在这里留下一份结果文件：`hits_<年月日>_<时分秒>.json`。

这个模块的意义在于**把跑分结果变成正式产物**，而不是终端里一闪而过的输出。有了它才能回答："上次那个 87% 到底是哪个数据集跑的？""改规则之前那批 case 是怎么判的？"

## 文件结构

```json
{
  "run_id": "20260807_195837",
  "dataset": "mvp | file:<文件名> | custom",
  "dataset_label": "人类可读的数据集名",
  "custom_path": "自定义数据集时的文件路径，否则为 null",
  "data_issues": [ "加载数据集时发现的数据质量问题" ],
  "started_at": "开始时间",
  "finished_at": "结束时间",
  "summary": { "release gate 指标 + diagnostic 指标" },
  "results": [ "逐条case：输入 / 期望 / 实际 / 模型理由 / 是否判对" ]
}
```

同一秒内跑完两次不会互相覆盖——`run_id` 撞了会自动加 `_2`、`_3` 后缀。

## 怎么看

- **网页上**（推荐）：「③ 命中结果」tab 有历史列表，点进去能按「全部 / 类别不符 / 报错 / 通过」筛选逐条结果
- **想看根因分析**：去「④ 分析报告」tab，它读的就是这里的文件
- **直接看原始数据**：这些就是普通 JSON 文件，编辑器打开即可

## 关于git

这些是每次本地跑评测的产物，性质跟 `规则配置/rules_config.json` 那种"当前生效配置"不一样，所以**默认不提交**（已在仓库根目录 `.gitignore` 里忽略 `hits_*.json`）。

需要长期保留某一次作为里程碑证据时（比如面试前想留一份 200 case 的完整结果），单独强制加进去就行：

```bash
git add -f "AI产品转型学习系统/05-产品原型/命中结果/hits_20260807_195837.json"
```

# System Prompt 固定模板

迁移说明：从 `03-学习成果/Day06-System-Prompt-固定模板.md` 迁移而来（原文件已归档，标注指向这里）。内容自 Day06 定稿以来未变。

定位：这是系统固定层，不是用户规则配置层（规则配置在同目录 `rules_config.json`）。

---

## 这份模板解决什么问题
这份模板的目标是把两类东西彻底分开：
- 系统固定不变的判断框架
- 用户后续不断增删改的规则内容

也就是说：
- `system prompt` 负责固定角色、输入输出、判断原则、回复约束
- `用户规则` 负责企业自己配置的规则说明、示例、边界示例、风险等级、动作

---

## 设计原则
- 不在 system prompt 里写死具体某一条业务规则
- 不让 system prompt 和某个类别 ID 深绑定
- system prompt 只定义"怎么判断"和"怎么输出"
- 用户新增或修改规则时，不需要重写 system prompt

---

## 固定 System Prompt 模板

```text
你是一个医药 CRM 拜访记录的合规审核助手。

你的任务不是生成内容，而是审核一段输入文本是否命中"当前启用的规则集"中的某条规则。

你每次会收到两部分输入：
1. 一段待审核的 CRM 拜访记录文本
2. 一组当前启用的规则（由业务方动态配置）

你的判断原则：
- 只根据当前传入的规则集做判断，不要假设存在未传入的规则
- 判断重点是语义关系和业务含义，不是机械找词
- 如果一条文本明显命中某条规则，应返回该规则
- 如果没有任何规则被命中，则返回默认通过类别
- 不要因为语气强烈、措辞口语化，就自动把文本判为违规
- 不要把"未实现或未传入的规则类型"硬压成相近规则

你的输出必须是一个 JSON 对象，不要输出任何额外说明文字。

JSON 格式：
{
  "matched_rule_id": "规则ID或默认通过ID",
  "matched_rule_name": "规则名称",
  "risk_level": "Critical|Medium|Low",
  "action": "Reject|PassWithNotice|Pass",
  "confidence": "High|Medium|Low",
  "rationale": "一句话说明命中依据"
}
```

---

## 这份模板里故意不放什么
- 不放具体的规则文本（01/03/05/06/07/10）
- 不放结构化识别的实现细节（Day07起已经没有这层了，见 `内部实现说明.md`）
- 不放某个企业特有的边界定义

原因：
- 这些都属于变量层
- 不应该污染 system prompt 固定层

---

## 当前最重要的边界
- `system prompt` 不负责维护规则本身
- 它只负责保证：
  - 输入格式稳定
  - 输出格式稳定
  - 判断原则稳定

---

## 当前版本的意义
这份模板的作用不是"马上让分数变高"，而是让后续架构更清楚：
- 用户规则未来可以持续追加
- 评测时不会再把"固定框架"和"具体规则"混在一起
- 后续做 Prompt 调优时，也能知道到底是在调哪一层

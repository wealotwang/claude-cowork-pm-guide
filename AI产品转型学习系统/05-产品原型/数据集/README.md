另外还有一个内置的 **MVP子集**（30条，`../规则执行/eval_cases.json`），是自己手写的小规模冒烟测试集，包含违规/边界/near-miss/兜底四种类型，跑得快、适合改完规则立刻验证一遍。它不在这个文件夹里，因为它是 JSON 不是 CSV，但网页上照样能选。

### 三个数据集分别回答什么问题

选哪个不是"越大越好"，是看你这次想验证什么：

- **MVP子集（30条）**：刚改完规则，想立刻知道有没有改坏 → 一分钟跑完
- **200case（200条）**：想知道当前这6类规则在大样本下稳不稳、边界样本会不会误伤 → 这是主力回归集
- **CSV50（50条）**：想知道离"完整10类产品"还差多远 → 拿来讲产品路线图，不适合拿来判断规则质量

## 表头兼容：不同数据集列名不统一怎么办

这两个数据集的表头其实对不上：

| 内部字段 | csv50 用的列名 | 200case 用的列名 |
|---|---|---|
| case编号 | `Case ID` | `ID` |
| 风险等级 | `风险等级` | `风险级别` |
| 预期动作 | `预期处置动作` | （没有这一列） |

以前 `run_eval_csv.py` 写死了 csv50 的列名，直接喂 200case 会 `KeyError` 崩掉。现在 `../规则执行/datasets.py` 里维护了一张列名别名表做归一化，两种表头都能读；缺失的列（比如 200case 没有预期动作）按"不比对这一项"处理，而不是报错。

要加新数据集，只要表头里能认出**分类ID**和**拜访记录文本**这两列就能跑（其余列缺了会用规则配置里的默认值兜底）。别名表在 `datasets.py` 的 `COLUMN_ALIASES`，加一个新叫法进去就行。

## 数据质量检查

加载数据集时会自动检查分类ID是否在 01-10 的体系内，有问题会在网页上提示。注意区分两种情况：

- **02 / 04 / 08 / 09**：不报错。这是"已知未实现"的类别，demo 主动收敛掉的范围，跑分时自然会miss，属于预期内
- **不在 01-10 内的ID**：会报数据质量问题。这是真的录入错了

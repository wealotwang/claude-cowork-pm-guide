## 3. 当前状态一句话总结
产品是**一个能用的本地网页工具**：[`05-产品原型/`](../05-产品原型/) 下 `python3 server.py` 起服务（或直接双击 [`启动网页.command`](../05-产品原型/启动网页.command)），浏览器里走完整闭环——① 规则配置 → ② 规则执行 → ③ 命中结果 → ④ 分析报告。

**规则taxonomy 2026-08-09刚做过一次重构**：从10类（当时只实现01/03/05/06/07/10六类）重组为**4个互斥的业务大类**（01商业贿赂和不良利益输送 / 02 PV和药品安全 / 03患者数据医生数据与患者隐私 / 04 Off-label推广与药物夸大疗效），全部升级为`Critical/Reject`，判断方式统一是LLM（不再有regex）。起因是从300 case真实误判里深挖两条高危漏判case（`MB005`/`MB251`），发现根因是01/06两个类别本该互斥却有业务重叠，顺藤摸瓜发现07也同时顶着04/08的定义——所以不是改prompt措辞，是重组了分类体系本身。详见 [Day08-学习卡.md](../03-学习成果/Day08-学习卡.md)。

**⚠️ 重要遗留问题**：`数据集/`下的CSV50、200case、300case（原版）三份数据集，`分类ID`列用的都是旧taxonomy编号，跟新的01-04编号不是同一套含义，拿它们跑新规则时"类别是否判对"这个指标会失真——只有 Release Gate 指标（Critical Recall/Medium Precision/Low FP Rate）是准的。新增的 `300case-简化二分类版-20260809.csv` 没有这个问题（本来就没有分类列，规避了这个坑），是当前推荐的主力压力测试集。

**最该做的下一件事：拿新的4类规则重跑简化二分类版300 case，看Release Gate指标，并设计一套适合"4类+二分类数据集"组合的评测指标**——旧的"按类别拆解"这张表在没有分类标注的数据集上会自动跳过，需要想清楚新版本下拿什么来判断"规则到底稳不稳"。

- `CHANGELOG.md`：记录完整决策链路，显式标注数据集分类ID尚未适配新版本的遗留问题
- `datasets.py`/`run_eval_csv.py`/`分析报告/report.py`/`index.html`：分类列改为可选，评测和报告全链路支持"无分类标注"数据集，`None`（不是`False`/`0`）表示"这个维度没有标准答案可比"，端到端用mock分类器验证过有/无分类标注两条路径
- 新增 `数据集/300case-简化二分类版-20260809.csv`（用户手动简化：去掉分类列，判断收敛成Critical/Reject vs Low/Pass两档）
- 修了"规则配置tab加载卡死"的真bug（前端fetch失败没有错误处理）；新增双击即用的 `启动网页.command`/`跑评测.command`，配合`.env`本地文件自动读取API key
- 详细文件列表见 `git show --stat <本次commit>`

### [关键决策]
- **不是所有漏判都该改prompt，先查分类体系本身有没有overlap**：从两条高危漏判case（`MB005`团建餐费换用量、`MB251`赠书号换独家处方权）深挖，发现根因不是模型判断能力，是01（商业贿赂）和06（讲课费/学术赞助对价化）的边界描述把判断标准错误地绑定在"走没走正规流程"这个表面形式上，而不是"好处有没有被当成换处方的条件"。系统性检查后发现07也同时顶着04/08的定义，属于同一类设计缺陷。完整过程见 [Day08-学习卡.md](../03-学习成果/Day08-学习卡.md)
- **taxonomy扁平化，不做"大类+子类"两层结构**：参考了外部材料的两层思路，但最终判断两层结构里子类之间照样可能互相打架，不如从一开始就把颗粒度定在"能完全互斥切割"的层面，代价是类别数量变少（10→4）
- **数据集兼容旧taxonomy是已知的、暂不处理的技术债**：CSV50/200case/300case（原版）三份数据集的分类ID还是旧编号，新规则下按类别拆解会失真，选择先用没有这个包袱的简化二分类数据集验证新规则，旧数据集重新标注留到以后

### [下一步]
1. 拿新的4类规则重跑简化二分类版300 case，看Release Gate指标
2. 设计一套适合"4类+二分类数据集"组合的评测指标（旧的"按类别拆解"在无分类标注数据集上会跳过）
3. CSV50/200case/300case（原版）的分类ID列重新标注成新taxonomy编号，这样才能拿它们测出有意义的类别准确率
4. 之后按排期推进：竞品/行业调研（Day09）→ 面试 README + 讲稿（Day10-11）

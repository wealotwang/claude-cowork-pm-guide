### 4. 用人话复述当前 6 条规则
- `01`：只要出现和处方量、进院、销量绑定的利益输送，就应该 `Reject`
- `03`：只要主动引导医生按未获批适应症、未获批人群、未获批线别或未获批给药方式使用产品，就应该 `Reject`

## Day07 第二轮：300 case Benchmark

### 1. 这轮数据集是什么
- 数据集：`/Users/li/Downloads/300 case-from gemini notebook-compliance checker - 2026.8.6.csv`
- 总用例数：`300`
- 当前模型：`deepseek / deepseek-v4-flash`
- 当前规则口径：`01 / 03 / 05 / 06 / 07 / 10`
- 这轮开始，dataset 不再把 `预期动作` 当主评测对象，runner 主要看：
  - 风险等级层的 Release Gate
  - 分类命中层的 Diagnostic

### 2. 300 case 主结果
- 成功跑完：`273`
- 报错：`27`
- 高危类 Recall：`87% (121/139)`
- 中危类 Precision：`96% (51/53)`
- 低危误报率：`5% (5/97)`
- Overall Exact Category Accuracy：`63%`
- Critical Exact Category Recall：`79%`
- Medium Recall：`80%`
- Overall Exact Action Accuracy：`97%`

### 3. 这轮结果怎么解读
- 和 `CSV50` 相比，`300 case` 更像一套围绕当前已配置规则扩展出来的压力测试，所以它不再主要暴露“完全没做的 6 类缺口”，而是更多检验当前 `6 类` 规则到底稳不稳
- 这也是为什么这轮分数明显高于 Day06 的 `CSV50`：
  - 高危 Recall 从 `50%`（CSV50 Day07）提升到 `87%`
  - 中危 Precision 从 `77%` 提升到 `96%`
  - 低危误报率仍然控制在 `5%`
- 但这并不代表系统已经成熟：
  - 仍有 `27` 条报错，主要是 LLM 空返回 / 截断 JSON / 非 JSON 输出
  - `05` 仍有低危样本被误拦截
  - `06` 有一部分样本会塌缩到 `01`
  - `02 / 04 / 08 / 09` 这些类在这轮 benchmark 里仍然没有真正命中分类

### 4. 已实现 / 未实现拆解
- 当前已实现类：`01 / 03 / 05 / 06 / 07 / 10`
- 这 6 类在 `300 case` 里一共占 `286` 条
- 其中成功跑完 `262` 条，分类完全命中 `188` 条
- 未实现类 `02 / 04 / 08 / 09` 一共只有 `14` 条，分类完全命中仍然是 `0`
- 所以这轮 `300 case` 更适合回答的问题是：
  - `当前 6 类规则到底稳不稳`
  - 而不是 `完整 10 类产品是不是已经做完`

### 5. 当前最值得盯的失败模式
- `05`：低危汇总统计样本偶尔被误判成 `05 / Reject`
- `06`：一部分“对价化学术支持”会被模型吸到 `01 商业贿赂`
- `04 / 09`：依然没有独立规则能力，相关 case 会落到 `07` 或 `10`
- 运行稳定性：`27/300` 报错，说明后面需要继续做输出 JSON 稳定性治理

## 这轮改动到底说明了什么
- 这不是一次“换模型就变强了”的提升，因为模型没变，还是 `deepseek-v4-flash`
- 这更像一次典型的 AI 产品规则迭代：
  - 先发现已知失败模式
  - 只改规则层描述与示例
  - 再用同一套 benchmark 重跑
  - 看分数是否有改善
- 当前结果说明：`05` 类规则层表达的补强，至少对完整 CSV50 有正向帮助

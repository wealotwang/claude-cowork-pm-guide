## 今日关键校准

### 1. Day06 不是再学一个概念，而是第一次拿真实结果证明方法
前几天主要在定义：
- 产品边界
- 规则模板
- eval 思路
- demo 架构

到了 Day06，学习重点开始切换：
- 不再只是“我觉得这个设计合理”
- 而是“它在评测集上到底跑出了什么结果”

这一步很重要，因为面试里最有说服力的不是“我想得很完整”，而是“我真的跑过、记过分、做过迭代”。

### 2. 先区分“规则是什么”“系统怎么判断”“评测看什么”
今天最大的结构性收获不是分数本身，而是把 3 层拆开了：
- 固定 system prompt：系统角色、输入输出、判断原则
- 用户规则配置：规则说明、示例、边界示例、动作
- 内部实现增强：结构化识别、调用链路、正则前置

这个拆分很重要，因为它决定了后面优化不会再混层：
- 改固定框架，不等于改规则
- 补结构化识别，不等于让用户去配 regex
- 评测先看 Recall / Precision / 漏报，不先陷进动作细节

### 3. 新学习方式对 Day06 特别合适
今天第一次把新方法用在 Day06 上，效果是明显的：
- `定焦` 让今天没有扩散到别的主题
- `主卡` 让问题聚焦在“能不能跑”
- `费曼复述` 让 Day06 的目标更容易讲给别人听
- `隔天回忆` 可以用于明天先复盘：Day06 到底卡在什么地方

今天回过头看，这套方式的价值很明显：
- 我们没有一上来就猜模型效果
- 而是先接通 DeepSeek，再直接拿真实分数说话
- 结果也更容易沉淀成作品集证据

### 4. 当前已知局限仍然有价值
MVP 子集评测里，当前唯一失败的是：
- `05-gap-1`
- 输入：`记录了特殊患者赵六的完整体检报告和电话号码以便后期随访`
- 期望：`05 / Block`
- 实际：`10 / Pass`

这个失败不是“意外翻车”，而是我们在评测集里提前埋好的一个已知局限：
- 这里没有具体手机号数字
- 当前 05 类只做了结构化 PII 正则
- 没有做“电话号码”这种非结构化敏感信息识别

所以它的意义很大：
- 说明 demo 没有假装自己全能
- 说明评测集不是只挑容易过的 case
- 说明我们已经知道下一步能力扩展应该往哪里补

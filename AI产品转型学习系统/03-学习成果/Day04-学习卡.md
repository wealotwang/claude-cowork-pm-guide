## 今日关键校准

### 1. 好的 eval 方案，不是“题越多越好”，而是“能支撑产品上线判断”
今天最大的认知更新不是再补几条 case，而是意识到：eval 的作用不是让文档看起来完整，而是帮助 PM 判断：
- 现在能不能上线
- 哪些风险是零容忍
- 哪些问题是体验问题、哪些问题是事故问题

### 2. 高危类和中低危类，不能用同一套指标逻辑
今天明确了一个非常关键的产品判断：
- 高危风险：优先 Recall（宁可错杀，不能漏报）
- 中低危风险：优先 Precision / 业务体验平衡

这也是为什么 HTML 方案里会把高危类要求设为 100% 召回，而把中低危更多交给精度与误报率控制。

### 3. 最容易误报的规则，往往不是“词命中问题”，而是“关系判断问题”
今天最重要的一个例子是“讲课费/学术赞助类”：
- 表面上看都可能出现“费用”“报销”“发票”等词
- 但真正决定是否违规的不是词本身，而是：
  - 有没有对价关系
  - 有没有和销量 / 进院 / 处方挂钩
  - 有没有超出正常学术活动边界

这说明：某些规则的难点在“语义关系识别”，不是简单关键词规则。

### 4. MVP 阶段允许刻意收敛 case，但必须知道删掉了什么
今天也明确了为什么不继续无节制扩 case：
- 目标不是做“最全的合规百科”
- 目标是做出一个几周内能跑、能讲、能演示的作品集 demo

因此当前 eval 方案可以先保留全貌，但 demo 阶段只先做一部分高价值子集。重点不是“全覆盖”，而是“知道自己没有覆盖哪些部分，并能讲清楚为什么先不做”。

---

## 今日得到的产品判断
- Eval 不是考试卷，而是 Release Gate
- 高危类和中低危类的评测目标必须区分
- 讲课费 / 学术赞助类是典型高误报风险区
- 当前阶段可以收敛 case 范围，但必须明确保哪些、舍哪些
